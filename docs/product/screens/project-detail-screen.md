# Project Detail Screen (MVP)

**Last updated:** 2026-03-23

## One-liner

The Project Detail screen answers: **"Where is this project right now, and what should I pick up next?"**

## Primary job

- Act as the deliberate backlog surface for one project.
- Help the user understand work shape, organize it, and choose the next accountable task.
- Provide the project-scoped entry point for shaping when the backlog still needs form.

## Surface posture

- Project Detail is project-scoped, not global.
- Project Detail is task-centric, not session-centric.
- The page is for choosing and organizing work, not for running the work itself.

## Core principles

- Tasks are the main visible unit of work on this surface.
- The page should establish project identity and current view clearly so backlog context is easy to read at a glance.
- Saved views belong here because they shape how the backlog is seen, not what the project means.
- Session entry from a task should stay easy and visible, but secondary to understanding the task itself.
- Shaping belongs here as a project-level backlog activity, but shaping sessions are not board tasks.
- Empty states should move the user toward shaping, creating accountable work, or starting accountable work with minimal ceremony.

## Key boundaries

- Fast global re-entry belongs to `docs/product/screens/home-screen.md`.
- Execution belongs to `docs/product/screens/session-screen.md`.
- Project-level configuration that changes workflow semantics belongs to `docs/product/screens/project-settings-sheet.md`.
